## The problem

Real estate auctions offer real discounts, but the information is scattered, every site uses its own format, and almost nobody shows whether the minimum bid is a good deal. Individual buyers give up before they start. Achalote gathers the lots, calculates the discount against the appraisal value, keeps the price history and alerts you when something changes. It starts with Caixa (Brazil's federal bank) properties in Rio de Janeiro. The product hasn't launched yet: what exists today is research, a specification, a design system and proofs of concept.

## How it's being built

### Research before code

I downloaded Caixa's official list (25,223 properties at collection time, 8,489 in RJ alone) and measured price, appraisal value and discount by sale type and state. I studied what already exists on the market and did a legal and cost survey. A product decision came out of it: the differentiator is the price-cut history, which only exists for whoever stores the list every day. That's why daily collection comes before any screen. The legal research also set limits: no debtor data, no stored property registry documents and no rehosted photos. This is a plan, not code: none of it is in production.

### Spikes that changed the architecture

I ran 44 verification points, confirming or refuting assumptions (27 confirmed, 8 refuted, 6 partial, 3 depending on a decision of mine). The most important one: I assumed Caixa would block datacenter IPs and planned to collect through GitHub Actions with a proxy. A temporary Cloudflare Worker downloaded all 27 lists and 45 detail pages, every one returning 200, and what the edge actually requires is a full set of browser headers. Collection became a Cron Trigger on the API Worker, with no proxy. I also ruled out the Astro adapter on Pages and Kysely's interactive transaction on D1. The proof of concept runs for a day: the exit criterion for phase 0 is seven days in a row with no intervention.

### Daily change detection, designed in steps

The list comes out around 10 pm Brasília time, confirmed by the `Last-Modified` header. The raw file goes to R2 before it is parsed. Processing validates format and volume (below 70% of the previous day is flagged as "suspect" and stops), compares against the database and generates events: listed, price reduced, sale type changed, financing changed, removed from the list and came back. A property missing for one day becomes "missing" before it becomes "delisted", so a collection failure doesn't produce a false event. Each relevant change closes one price snapshot and opens another. This algorithm is specified in detail but not implemented yet.

### A design system that already exists

This part is already in the repository: color and typography tokens, light and dark themes and components (property card, price, discount badge, filter drawer), with a live reference route. Product rules become interface rules: every number shows its source and date, risk appears next to the opportunity, the discount rounds down and the cost rounds up, and the interface never gives a verdict like "this is safe". I measured color contrast with a script.

## Architecture decisions

- **Three Workers with separate roles.** Astro for the landing page and SEO, TanStack Start for the logged-in app and Hono for the REST API, so SEO stays static and fast and the app can evolve without affecting the public pages.
- **D1 with Kysely and a repository layer.** Since D1 has no interactive transactions (proven in the spike), the unit of work is the `batch`, which is atomic. Tables and columns are in English, with a comment on every column checked by a test.
- **Explicit caching.** Cache API in the Workers and purge by tag, because the zone's cache rules don't cover responses generated by a Worker.
- **Store the raw data before parsing it.** If the parser gets it wrong, I reprocess the file from R2 and the history isn't lost.
- **Narrow scope.** Phase 0 only collects, phase 1 is free and has no login, and billing only comes in if validation passes. The planned billing uses Araute.
